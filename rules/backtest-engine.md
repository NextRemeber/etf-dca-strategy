# ETF 回测引擎硬性口径（权威源）

> 所有策略验证脚本必须遵守。违背后结论作废。
> **2026-08-21 起统一引擎为 `research/engine/backtest_core.py`，禁止再复制 simulate 逻辑副本**
> （v1.0 时代的卖出成本 bug 之所以扩散到 9 个文件，根源就是复制粘贴式引擎）。

## 一、现金与交易口径（防"免费印钱"）

1. **现金储备制**：月初预算入账现金池，投资时 `cash -= amt`（**mult>1 时尤其必须扣**）
   - 历史 bug：`simulate_graded` 中 3x/2x 加仓 shares 增加但 cash 不扣 → 低位多投的钱凭空出现 → **IRR 平均虚高 5.51pp**（新能源 +7.7pp、地产 +10.6pp 最重）
2. **不透支**：`amt = min(monthly * mult, max(cash, 0))`——低位 3x 必须靠前期积累
3. **现金计息**：未投部分按货基 2% 年化计息（`cash *= (1 + CASH_RATE/252)`）
4. **成本**：买入按 0.15% 扣费（`shares += amt * (1 - COST) / p`）
5. **卖出成本从现金侧扣（v1.1 硬性）**：卖出市值 V → `shares -= V / pl; cash += V * (1 - COST)`
   - **禁止** `shares -= V*(1-COST)/pl; cash += V`（B1 bug：每笔凭空 +V×COST）
   - **禁止** 现金与份额同时乘 (1-COST)（div_momentum 变体：成本凭空消失）

## 二、IRR 计算（防发散与口径欺骗）

1. **牛顿迭代在亏损组合发散** → 一律用**二分法**，区间 `[-0.99, 10.0]`，80 次迭代
2. **IRR 口径会骗人**：少投（0.25x 减投月）会让 IRR 虚高，因为分母小
   - 判据：**资产口径（总终值/总投入）与 IRR 双看**；两者矛盾时以资产口径为主
   - 历史教训："分档 IRR +18.29% 高是因只投 70% 预算"——纯定投 90,051 vs 分档 89,187 实际打平
3. **现金入账必须与调仓/旋转频率独立**：cash 注入固定每月 1 次，轮动/加投频率另算
   - 历史 bug：高频旋转（每周/双周）在 is_first 标记同时入资 → IRR 虚高 +73%

## 三、数据与未来函数

1. **前一日打分**：`scores.shift(1)` 后才可用于当日执行（防未来函数）
2. **买卖必须按当日价格成交**（份额×当日价），**禁止"昨日净值×成本"虚拟成交**：
   - 历史 bug（2026-08-20）：`nav *= (1-COST)` 净值复利法在"先止盈/切换、后更新净值"顺序下，止盈日未计入当日回撤下跌 → 等效以昨日价卖出今天的下跌 → 179 次交易收益虚高 20 倍（2688%→真实 118%）
   - 判据：任何持仓变动日，成交金额必须用**当日价格**；净值复利写法（nav×p/entry）只允许在无交易的日子使用
3. **fillna(0) 吞掉 NAV**：不同起始日 DataFrame 组合时 0 填充 → NAV 跌到 0
   - 修正：`concat + ffill` 统一索引；价格查找用统一索引 `prices[c]`，**禁止** `dict.get(dt, 0)` 兜底
4. **预热期**：打分需 60 日历史预热，`bull_align` 需 300+ 日数据；数据不足的标的直接跳过而非默认值
5. **单位检查**：阈值类参数确认单位（历史 bug：take_profit 阈值写 15 实际应为 0.15 的百分比口径）

## 四、输出与报告

1. 每次验证必须输出：总投入 / 总终值 / IRR / 最大回撤 / Calmar
2. 组合级对比必须三窗口：全窗口 + 前段 + 后段（防止单窗口偶然）
3. 关键结论附机制解释——无机制解释的结果视为可疑（可能是过拟合或 bug）

## 五、引擎发布前强制三查 → 三账守恒审计（v1.1，2026-08-21 升级）

> 升级原因：v1.0 三查（成交价/未来函数/现金恒等式）**全部通过**却漏检了卖出成本符号 bug——
> 因为旧审计"复刻引擎逻辑"对账，引擎错它就跟着错。新原则：**审计代码绝不复制引擎逻辑**。

| 检查 | 方法 | 判据 |
|------|------|------|
| A 成交价基准 | 逐笔交易价格 vs 当日价格（折价通道按折价规则核对） | 全部一致 |
| B 现金账 | 仅凭交易日志独立重放现金流水 vs 引擎日账 | 逐日误差≈0 |
| C 份额账 | 仅凭交易日志独立重放份额 vs 引擎日账 | 逐日误差≈0 |
| D 财富守恒 | ΔNAV == Δ持仓市值 + Δ现金（费用/入金/货基息全入账）；**NaN 账目显式判错**（NaN 比较恒 False 会漏检） | 逐日误差≈0，无 NaN |
| E 现金不透支 | 逐日 cash ≥ 0 | 0 透支 |
| F 无未来函数 | 抽样验证引擎用分数 = 前日分数（shift1） | 全部一致 |
| G 回归用例 | 已知 bug 写法（如 `shares-=V×(1-C)/pl; cash+=V`）必须被 D 检出 | 审计有检出能力 |

实现：`research/engine/engine_audit.py` + `backtest_core.audit_conservation()`。
**新增/修改引擎必须 A-G 全过后才可发布结论。** 统一引擎 backtest_core 2026-08-21 审计：三配置 A-F 全过 + G 检出力验证 ✅。

## 七、数据管道口径（v1.1 新增）

1. **唯一写入位置**：仓库 `data/ic_cache/`（fetch_ohlcv 不再写外部路径）
2. **增量更新**：末条距今 >4 天 → 拉尾部 45 天；重叠段单日偏差 >0.1%（前复权因分红重算）→ 全量重拉
3. **日报防陈旧**：final_strategy 启动即检查核心标的缓存末条，>5 天醒目告警；`--refresh-data` 增量刷新
4. **加载规则**：qfq_*/ohlcv_* 两套缓存取末条更新者（防 B5 遮蔽）
5. **溢价序列口径**（2026-08-21 重建）：`premium = raw 收盘价 / 东财官方单位净值 - 1`（同日期对齐）；**禁止用 qfq 价格算溢价**（513100 于 2025-05-12 份额折算，qfq=raw×0.5614，混用会导致 2025-05-12 前溢价失真）；重建脚本：东财 LSJZList 分页拉净值 + 腾讯不复权日线（`_prem_build` 保留临时产物待入库）；回测 defl 通道已知 qfq/raw 口径混用（2025-05-12 前成交价偏低 44%），仅作乐观界方向参考
